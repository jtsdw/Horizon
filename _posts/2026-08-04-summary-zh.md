## [LiveMem：为长时间运行的 LLM 推理提供持久记忆状态](https://arxiv.org/abs/2608.02515v1) ⭐️ 8.0/10

LiveMem 提出了一种内在记忆方法，为预训练的全注意力 LLM 增加一个记忆状态，在上下文切换时保留历史信息，同时保持有界的 KV 窗口。在 LongMemEval 上的实验表明，即使支持证据从当前上下文中移除，它也能回答问题。 这解决了长时间运行的助手和智能体中的一个关键限制，即上下文窗口是有限的，最终会被耗尽。通过提供持久的状态连续性，LiveMem 可以使 AI 系统在长时间交互中更加可靠和上下文感知。 LiveMem 结合了上下文切换、面向记忆的后训练和状态感知服务，使记忆状态在原始 token 释放后仍能承载信息。证据距离分析表明，有用信息在活动窗口之外仍然存在。

rss · arXiv LLM Inference · 8月3日 17:12

**背景**: 在 LLM 推理中，KV 缓存存储中间键和值计算以加速生成，但其内存占用随上下文长度增长。长时间运行的任务常常超出上下文窗口，而现有的摘要或检索方法只能提供对历史的选择性访问，不能提供持久状态。LiveMem 旨在通过维护一个独立于活动上下文的固定容量记忆状态来填补这一空白。

## [UDP 广播提升边缘 MoE 推理；Wi-Fi 54 Mbps 上限成瓶颈](https://arxiv.org/abs/2608.02341v1) ⭐️ 8.0/10

研究人员提出了一种用于边缘设备上分布式混合专家（MoE）推理的 UDP 广播方法，在有线 8 节点集群上相比 NCCL 和 TCP 实现了稳定的 1.4 倍加速。他们还发现 IEEE 802.11 将广播速率限制在 54 Mbps，这一遗留策略严重限制了无线边缘 AI 的性能。 这项工作揭示了无线边缘 AI 推理中的一个关键瓶颈，并提出了一种利用 UDP 广播一对多效率的实用解决方案。它还呼吁 Wi-Fi 标准重新考虑广播速率限制，这可能为协作边缘计算应用带来显著的性能提升。 该方法利用分布式 MoE 中近乎确定的延迟，采用超时驱动的重传机制来保证可靠性，并通过无序结果收集来处理专家预测错误。在 1 米、2 米和 5 米距离下的 NS-3 模拟显示，最优广播速率分别比 54 Mbps 上限高出 64 倍、43 倍和 32 倍。

rss · arXiv LLM Inference · 8月3日 14:57

**背景**: 混合专家（MoE）模型实现稀疏激活，允许将大型模型分布到多个边缘设备上。分布式 MoE 推理涉及一对多通信，使用 NCCL 和 TCP 等传统单播协议效率低下，但天然适合 UDP 广播。然而，由于遗留标准是为控制流量而非高吞吐量数据设计的，Wi-Fi 的广播速率被限制在 54 Mbps。

## [资源公平调度提升批量 LLM 服务效率](https://arxiv.org/abs/2608.02244v1) ⭐️ 8.0/10

本文正式化了批量 LLM 服务中的资源分配低效问题，并提出了一种资源公平调度策略——插入短任务并限制（ISJL）算法，该算法具有至少 3/4 的竞争比保证。 这项工作解决了 LLM 服务系统中的关键瓶颈，即批处理中异构请求导致不成比例的延迟和 GPU 资源消耗。所提出的算法为提高吞吐量和成本对齐提供了实用解决方案，惠及云服务提供商和商业 LLM API 用户。 ISJL 算法是一种参数化的混合批处理策略，限制了同批请求之间解码进度（KV 缓存占用）的差异。数值实验表明，ISJL 在 FCFS（批处理外部性大）和 LJF（成本对齐但灵活性差）之间取得了有利的中间地带，在保持高吞吐量的同时，将最大驱动批处理成本与按 token 计费的收入对齐。

rss · arXiv LLM Inference · 8月3日 13:55

**背景**: 在批量 LLM 服务中，请求共享解码批次，批处理步骤的墙钟时间成本主要由最大的活动 KV 缓存占用决定。这意味着短请求与长请求同批处理时，可能会经历与其自身 token 工作量不成比例的延迟和 GPU 资源消耗。本文将此形式化为资源公平调度问题，将批内公平性与系统吞吐量联系起来。竞争比是在线算法分析中的标准指标，用于比较在线算法与最优离线解的性能。

## [TELLER：面向 LLM 推理的非侵入式跨层根因分析框架](https://arxiv.org/abs/2608.01975v1) ⭐️ 8.0/10

TELLER 是一个新框架，它无需修改模型二进制文件，即可从 NVTX/CUPTI 跟踪和服务日志中重建每个请求的调用链树，从而实现对 LLM 推理的跨层根因分析。它引入了依赖感知的因果上下文切片和 Trace Pair Encoding（TPE）分词器来压缩跟踪数据，并将数值候选定位与多模态根因模型相结合。 这解决了 LLM 推理可观测性中的一个关键空白，因为当前的性能分析工具和日志无法捕获跨层执行语义和请求级结构。通过实现高效准确的根因分析，TELLER 可以显著改进 LLM 服务的调试和优化，而 LLM 服务正越来越多地作为持续运行的系统部署。 在多节点 GPU 推理工作负载上的实验表明，适度的 TPE 词汇表可将每步跟踪长度减少 80%以上，同时在水平（跨节点通信）和垂直（节点内执行栈）视图上均取得最佳整体性能。更激进的压缩会显著降低诊断质量，并且在低故障先验、强化基线和模态消融下的进一步分析证实了 TELLER 的实用性。

rss · arXiv LLM Inference · 8月3日 09:39

**背景**: LLM 推理已从离线工作负载演变为持续运行的服务，但由于单个请求跨越多个层（推理引擎、Python/C++后端、主机 CUDA API、GPU 内核和分布式通信），根因分析变得困难。现有的性能分析工具（如 NVTX 和 CUPTI）提供原始时间线，而基于日志的诊断常常遗漏跨层执行语义。TELLER 通过以非侵入方式结合跟踪和日志，并使用受 Byte Pair Encoding（BPE）启发的分词器来压缩结构化跟踪数据，从而解决了这一问题。

## [LaCache：抵御缓存碰撞攻击的鲁棒语义缓存方案](https://arxiv.org/abs/2608.01718v1) ⭐️ 8.0/10

LaCache 提出了一种新颖的 LLM 服务语义缓存方案，该方案不仅检查查询的缓存命中，还检查其前 k 个推测解码令牌的缓存命中，从而为抵御缓存碰撞攻击提供了形式化保证。这一重新设计还通过为缓存索引增加额外的语义上下文，提高了响应相关性。 这项工作解决了语义缓存中的一个关键安全漏洞，而语义缓存已被广泛用于降低 LLM 服务的成本和延迟。通过提供一种有原则且具有形式化保证的解决方案，LaCache 可以使语义缓存在生产系统中更安全地部署，防止可能破坏响应的对抗性攻击。 关键洞察在于，虽然攻击者可以完全控制对抗性查询，但其对响应的控制有限，因为响应必须同时满足多个语义约束。LaCache 证明了不可能构造出同时引发恶意响应并与良性查询冲突的对抗性查询，并且跨多种 LLM 和基准的实证评估验证了其安全性和效率提升。

rss · arXiv LLM Inference · 8月3日 05:31

**背景**: 语义缓存存储 LLM 响应，并为语义相似的查询重用这些响应，从而降低延迟和成本。然而，现有方案容易受到缓存碰撞攻击，攻击者通过注入精心构造的查询来污染缓存，并破坏对合法请求的响应。推测解码是一种技术，它廉价地生成多个候选令牌并并行验证，LaCache 利用该技术来检查解码令牌的缓存命中。
