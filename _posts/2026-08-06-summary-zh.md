## [RAC：面向分割式大模型推理的参考感知压缩](https://arxiv.org/abs/2608.04991v1) ⭐️ 8.0/10

本文提出了 RAC，一种参考感知的激活压缩编解码器，通过利用历史片段和因果预测器来降低分割式大模型推理中的通信开销。在三个模型和九组模型-链路组合上，TTFT 加速 1.24-2.72 倍，TPOT 加速 1.01-2.79 倍。 分割式大模型推理是隐私保护和高效部署的有前景方案，但通信瓶颈限制了其实用性。RAC 直接解决了这一关键瓶颈，有望在真实应用中实现更高效、更私密的大模型服务。 RAC 采用分组仿射对齐和带可选预填充离群值的校准残差量化，并通过发送端线格式重建同步后续参考。12 项非困惑度任务分数变化范围为-0.40 至+2.50 分，表明质量影响很小。

rss · arXiv LLM Inference · 8月5日 16:01

**背景**: 分割式大模型推理在本地执行模型的头部、尾部和工具，而中间层在云端运行，但这需要在每次调用时传输边界隐藏状态，造成通信瓶颈。像 RAC 这样的激活压缩编解码器旨在通过压缩传输前的隐藏状态来减少开销，利用数据中的模式提高效率。

## [LLM 基准分数随推理后端选择而变化](https://arxiv.org/abs/2608.04714v1) ⭐️ 8.0/10

一项新研究揭示，推理后端（如 HuggingFace、vLLM、Ollama）的选择可以显著改变 LLM 基准分数，即使在无采样噪声的贪婪解码下也是如此。研究发现，后端选择约占从业者开箱即用所见变异的 39%。 这一发现挑战了将基准分数作为模型属性报告而不披露推理框架的常见做法，削弱了 LLM 研究的可复现性。它突出了一个隐藏的变异来源，可能影响机器学习社区的模型比较和部署决策。 该研究采用完全交叉设计，涉及三个指令调优模型、五个推理框架、六个基准和四种生成模式。后端的影响是结构性的，且强烈依赖于模型，在事实性基准上的差异比在社会偏见基准上更明显。

rss · arXiv LLM Inference · 8月5日 11:28

**背景**: 推理后端是执行 LLM 推理的软件框架，如 HuggingFace Transformers、vLLM 和 Ollama。贪婪解码是一种确定性解码方法，每一步选择概率最高的 token，消除了采样噪声。该研究表明基准数字并非与后端无关，建议披露后端、版本和生成配置，并使用确定性解码进行跨后端比较。

## [Agentic AI 工作流的首次架构特征分析](https://arxiv.org/abs/2608.04458v1) ⭐️ 8.0/10

本文基于微软 Azure 的生产研究和开源框架的对照研究，首次对 agentic AI 工作流进行了架构特征分析。研究发现 agentic 执行是碎片化和异构的，请求会扩展为反复跨越 CPU-GPU 边界的工作流。 这些发现揭示了传统统一服务器在架构上的不匹配，可能导致 CPU 和 GPU 容量闲置以及微架构局部性下降。这对数据中心和系统设计具有重要意义，为未来 agentic AI 工作负载的软硬件协同设计提供了指导。 论文提出了 agentic 工作流的分类法，并提出了 Agora 原型，用于商用服务器，动态回收空闲 CPU 核心，超订 GPU 内存，并按角色池化核心并采用亲和性调度。Agora 在保持 agent 尾部延迟的同时提高了利用率和吞吐量。

rss · arXiv LLM Inference · 8月5日 05:31

**背景**: Agentic AI 指的是自主代理通过编排多个步骤（包括 LLM 推理、工具调用和决策）来执行任务的系统。在数据中心中，这些工作流不同于传统的批量推理（主要受 GPU 限制），因为它们涉及大量的 CPU 活动以及频繁的 CPU-GPU 边界跨越。

## [AsymSpec：非对称网络下的高效云边投机解码](https://arxiv.org/abs/2608.04974v1) ⭐️ 8.0/10

AsymSpec 引入了非对称验证和基于 TV 证书的升级机制，以提高非对称网络下投机解码的效率。与最强基线相比，其输出令牌吞吐量提升了 2.82 至 28.03 倍。 这解决了云边 LLM 推理中的实际瓶颈，即上行链路限制和无效的依赖工作限制了吞吐量。它可以使大型模型在边缘设备上的部署更加高效，从而惠及实时应用。 非对称验证协议保持常见路径的接受上传紧凑，并将仅拒绝的纠正信息移至下行链路。TV 证书决定较小的目标 top-K 响应是否足够，必要时逐步升级到精确恢复。

rss · arXiv Speculative Decoding · 8月5日 15:45

**背景**: 投机解码使用小型草稿模型生成候选令牌，由较大的目标模型并行验证，从而提高推理速度。在云边设置中，草稿模型在边缘运行，目标模型在云端，但通信开销和非对称带宽可能限制收益。AsymSpec 针对这些挑战。

## [SpecRoll：用于投机强化学习回滚的快慢自适应方法](https://arxiv.org/abs/2608.04962v1) ⭐️ 8.0/10

SpecRoll 提出了一种用于 RL 后训练的投机回滚引擎，通过快速未来词元头和慢速参数更新来适应不断变化的目标策略，在五个模型和三个数据集上，相比 vanilla GRPO 实现了 1.26-2.15 倍的生成加速和 1.21-2.04 倍的端到端加速。 这解决了 LLM RL 后训练中自回归回滚生成缓慢的关键效率瓶颈。通过保持采样分布和 GRPO 目标，SpecRoll 可以在不牺牲质量的情况下加速训练，可能使大规模模型的 RL 后训练更加实用。 SpecRoll 使用轻量级未来词元头进行并行提议，并使用 Reflex 模块，通过延迟验证器反馈进行有界、轨迹局部的隐藏状态修正，无需反向传播。它还包括一个慢速路径，仅在检测到持续退化时更新头部参数，并使用并发感知的稀疏树验证和精确目标验证。

rss · arXiv Speculative Decoding · 8月5日 15:32

**背景**: 强化学习（RL）后训练增强了 LLM 的推理能力，但受限于缓慢的自回归回滚生成。投机解码通过使用草稿模型提出多个词元，并由目标模型并行验证来加速生成，但在 RL 中应用它很困难，因为目标策略不断变化，导致静态草稿模型过时，频繁更新成本高昂。SpecRoll 通过双时间尺度自适应解决了这个问题，结合快速未来词元头和慢速参数更新，在不改变采样分布的情况下保持效率。
