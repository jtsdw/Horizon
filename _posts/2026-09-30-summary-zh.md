## [德里将电力损耗从 50%降至 5%](https://spectrum.ieee.org/delhi-electricity-loss) ⭐️ 8.0/10

## [上下文语言模型将上下文作为文件自主管理](https://arxiv.org/abs/2609.37725v1) ⭐️ 8.0/10

一篇新论文提出了上下文语言模型（CLM），将上下文视为模型可以自由更新的文件，而非依赖外部框架控制。用现有模型零样本构建的 CLM 据称超越了当前最先进的上下文管理策略，在 BrowseComp-Plus 上准确率提高 11.4%且 FLOPs 减少 21.5%，在 12 小时 EdgeBench 任务上得分提高 5%且 FLOPs 减少 59%。 这项工作将上下文管理从外部编排转变为模型的内在行为，可能重塑长上下文和智能体 LLM 系统的设计方式。该方法自然扩展到多个智能体上下文作为文件共存的多智能体系统，并使上下文管理策略能够进行上下文学习和参数化学习。 CLM 可以通过标准技能优化循环演化出的自然语言指令进行引导，在上下文管理任务上将留出准确率提高最多 35.9 个百分点，同时减少计算量。作者还提出了一种在线强化学习方法，使 Qwen3.5-9B 在 BrowseComp-Plus 上性能提升 47.6%且 FLOPs 减少 12%，并共同设计了用于 CLM 服务的后缀缓存复用，在同等性能下将服务器端计算量较标准 SGLang 减少 35%。

rss · arXiv LLM Inference · 9月29日 14:50

**背景**: 上下文管理指的是语言模型在工作上下文增长时如何决定保留、总结或丢弃哪些信息，这是长时间运行的智能体和深度研究系统的核心挑战。BrowseComp-Plus 是源自 BrowseComp 的基准，使用固定的精选语料库、人工验证的支持文档和挖掘出的困难负样本，以公平评估深度研究智能体。EdgeBench 是一个真实世界任务基准，用于评估自主 AI 智能体如何在资源受限环境中学习。FLOPs（浮点运算次数）是衡量模型运行计算成本的常用指标。

## [SPLASH 在 LLM 服务过程中动态切换注意力并行布局](https://arxiv.org/abs/2609.37626v1) ⭐️ 8.0/10

SPLASH 是一个服务系统，能够在请求运行过程中动态切换注意力的并行布局（张量并行、数据并行或上下文并行），其核心依据是现代注意力机制在 KV 头很少或没有 KV 头时，将请求的 KV 缓存位置与注意力权重分片方式解耦。它提出了解耦所有权并行（DOP）和感知转换的调度器，切换开销中位数低于单步的 0.51%，在 B200 GPU 上服务 GLM-5.3 时相比固定布局部署实现了 1.3–1.73 倍的端到端吞吐提升。 固定的注意力并行布局与推理、智能体和 RL rollout 等批次特征在运行中变化的工作负载之间的不匹配日益严重，而 SPLASH 表明布局切换几乎可以零成本完成，无需排空请求和重启工作进程。这对 LLM 服务引擎具有直接的实用价值，有望在多样化的动态工作负载下提升吞吐量和 KV 容量利用率。 这种解耦催生了解耦所有权并行（DOP），它像张量并行一样分片注意力权重，同时像数据并行注意力一样将每个请求的缓存保留在单一所有者上，在不复制权重或缓存的情况下比数据并行注意力提供 27–60% 更多的 KV 容量。相同的布局规律也出现在 H200 上的 DeepSeek-V3.2 和 DCU 上的 GLM-5.3-Flash 上，不过评估主要聚焦于特定的模型和硬件组合。

rss · arXiv LLM Inference · 9月29日 14:02

**背景**: 大型语言模型服务引擎使用张量并行（分片权重和注意力头）、数据并行（复制模型并拆分请求）和上下文并行（拆分长序列）等策略在多 GPU 上并行化注意力。每种布局在不同条件下各有优势：低并发适合张量并行，大量独立请求适合数据并行注意力，长提示适合上下文并行。KV 缓存存储已生成 token 的键和值，其放置位置和内存占用对服务效率至关重要，尤其是在使用很少或没有 KV 头的现代注意力变体中。

## [Purlin 将 GPU 集合通信的编排与数据通路解耦](https://arxiv.org/abs/2609.36954v1) ⭐️ 8.0/10

一篇新的 arXiv 论文（2609.36954v1）由 Christos Kozyrakis 等人提出 Purlin，这是一个 scale-up 通信框架，将集合通信的语义、编排和数据通路分为三层：输入输出布局与拷贝/归约操作的规格说明、SNAC（Stage, Notify, And Consume）编排协议，以及名为 Atom 的硬件相关数据通路。在 A100、H200 和 B200 GPU 上对七种集合通信进行评测，Purlin 相比基线最高实现 5.14 倍延迟加速和 4.50 倍带宽提升；集成到 SGLang 后，离线 LLM 服务吞吐平均提升 1.13 倍，在线推理交互性最高提升 2.85 倍。 集合通信是分布式推理的关键瓶颈，而现有实现把语义、编排和数据通路紧密耦合，导致采用新硬件机制或为特定工作负载定制通信的成本很高。通过清晰分离这些关注点，Purlin 有望降低硬件厂商和系统构建者接入新互连或加速器的门槛，同时复用共享的编排协议，从而可能影响未来集合通信库和推理引擎的设计方式。 Purlin 将每种集合通信指定为输入输出布局的命名加上拷贝或归约操作，SNAC 从这些规格中推导出协调逻辑，而 Atom 只实现两个数据移动原语：拷贝和归约。评测覆盖 A100、H200 和 B200 GPU 上的七种集合通信；与 SGLang 集成后，在线交互性在过载情况下增益最大（最高 2.85 倍），扩散图像生成的端到端延迟最高降低 1.13 倍。

rss · arXiv LLM Inference · 9月29日 07:57

**背景**: GPU 集合通信指的是 all-reduce、all-gather、broadcast 等协调式数据移动操作，用于在多块 GPU 之间同步和共享数据，是大模型分布式训练和推理的基础。NCCL、RCCL 等库实现了这些集合通信，但通常把协调逻辑和底层数据移动硬编码在一起，因此支持新的互连或加速器往往需要重写栈中的大量部分。Purlin 的贡献在于架构层面：它把一次集合通信拆分为声明式规格、可复用的编排协议（SNAC）和轻量的硬件相关数据通路（Atom），新硬件只需实现拷贝和归约即可接入。

## [SelfSearch：无需奖励信号的 LLM 智能体自我改进方法](https://arxiv.org/abs/2609.37968v1) ⭐️ 8.0/10

SelfSearch 提出了一种无需奖励信号的搜索流程，让 LLM 智能体通过从以往自我修改记录中学习来改进自身，这些记录包含先前修改尝试的推理过程、工具操作和结果。在搜索过程中完全不使用下游奖励信号的情况下，该方法在全部六种模型-基准组合中都提升了群体平均成功率，单个智能体在 Terminal-Bench 2.1 上最高提升 11.2 个百分点，在 SWE-bench Multilingual 上提升 5.0 个百分点，同时将执行成本降低 38.5%。 这解决了现有自我改进方法的一个关键局限：它们依赖反复的下游评估，成本高昂且使搜索与特定任务绑定。通过将自我改进与奖励信号解耦，SelfSearch 有望让智能体进化更便宜、更通用，这对任何构建或部署自主编程智能体的人都具有重要意义。 SelfSearch 仅用 4.03 美元的搜索成本，就生成了一个在公开九种 harness 对比设置下、使用 DeepSeek V4 Flash 解决 82.0% Terminal-Bench 2.1 任务的 harness，与得分最高的 harness Codex 持平。它以更低的搜索成本达到了与评估引导搜索基线相当的任务成功率，不过这些提升是相对于初始智能体而言，而非绝对的最先进水平。

**背景**: LLM 智能体是能够检查和修改自身指令、工具及执行流程的 AI 系统，这一能力随着编程模型的发展而不断增强。现有的自我改进方法利用这种能力，通过反复的下游评估来搜索更好的智能体，但这种方式成本高昂且与任务绑定。Terminal-Bench 2.1 和 SWE-bench Multilingual 分别是衡量智能体在终端任务和多语言软件工程问题上表现的基准。
