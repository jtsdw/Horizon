## [Fish Audio Drama 3：35B MoE 语音模型实现导演式表演生成](https://arxiv.org/abs/2610.18010v1) ⭐️ 8.0/10

Fish Audio 发布了 Drama 3，这是一个开源的 35B 参数混合专家语音生成模型，每个 token 激活 3B 参数，可将文本转化为带有导演指导的表演。它在单一模型中引入了多轮修订、场景配音、基于填充的编辑和流式合成，模型权重已在 GitHub 和 Hugging Face 上发布，并可通过 SGLang-Omni 进行推理。 这是表现力语音合成领域一项重要的开源进展，将大型 MoE 主干网络与新颖的编辑和流式能力相结合，可能重塑语音内容、配音和交互式音频的制作方式。相比更小的 Fish Audio S2，它在效率上的提升表明 MoE 扩展可以同时带来更高质量和更快推理，惠及 AI 音频生态中的开发者和创作者。 Drama 3 将混合线性注意力主干与一种新的码本多 token 预测音频解码器相结合，该解码器在专用层中预测每一帧的声学码本，并关注整个序列。它通过三阶段预训练配方、指令微调以及仅使用单一学习到的人类偏好奖励的大批量强化学习进行训练；其推理引擎在单张 H200 上以每秒 271 帧解码单流，而 Fish Audio S2 为 177 帧，尽管 Drama 3 的参数数量是后者的七倍多。

rss · arXiv LLM Inference · 10月13日 09:06

**背景**: 混合专家（MoE）是一种神经网络架构，它用多个专门的专家网络替代密集前馈层，每个 token 只激活其中一部分，从而在保持计算效率的同时扩展参数量。混合线性注意力主干将线性注意力与全注意力结合，以在效率和长上下文召回之间取得平衡；多 token 预测解码器则在每次前向传播中生成多个未来 token 以加速推理。Drama 3 基于这些技术，从文本生成富有表现力、可编辑且可流式传输的语音。

## [大规模技能库下 LLM 智能体出现技能路由崩溃](https://arxiv.org/abs/2610.18522v1) ⭐️ 8.0/10

一篇新的 arXiv 论文（2610.18522v1）表明，LLM 智能体会出现“技能路由崩溃”：当技能库中加入无关技能时，智能体加载的相关技能越来越少甚至完全不加载。当无关技能达到 1000 个时，已加载技能召回率从 73.6%降至 27.4%，零加载率从 9.3%升至 51.6%，而同一技能库下的显式预选仍保持 73.9%的召回率。 这一发现揭示了当前流行的 LLM 智能体可复用技能库设计存在根本性的可扩展性瓶颈，因为其执行依赖于对技能元数据的隐式路由。随着技能库增长到数百甚至数千条，这对智能体架构、技能协议设计以及评估方法都有直接影响。 这种下降并不能用智能体加载了其他技能（包括金标准技能的合理替代项）来解释；仅屏蔽无关技能的描述即可大幅恢复技能加载，说明描述带来的语义干扰是主因。即使元数据完整，显式要求智能体规划技能使用，其召回率仍低于预选方案；论文还评估了显式预选作为缓解手段在覆盖率和延迟上的权衡。

rss · arXiv Agent Infra · 10月13日 15:12

**背景**: LLM 智能体越来越多地依赖可复用的“技能”（任务特定的指令或工具），这些技能按需加载而非一次性全部注入，因为上下文窗口无法容纳数万条技能。这使得智能体根据元数据描述将任务隐式路由到正确技能的能力变得至关重要。SkillsBench 是一个评估此类技能增强在智能体任务中效果的基准，而 SkillRouter 等先前工作已探索了面向大型技能注册库的检索与重排序方法。

## [Kairos：面向 LLM 代理的事务性安全执行机制](https://arxiv.org/abs/2610.18457v1) ⭐️ 8.0/10

研究人员提出了 Kairos，一种部署在未经修改、不透明的 LLM 代理隔离边界上的引用监视器，它调解代理产生的效果而非单个动作。在 AgentDojo 基准上，Kairos 将攻击成功率从 47.0%降至 2.7%，同时良性任务的效用保持在未防御代理的水平。 间接提示注入是代表用户行使权限的 LLM 代理面临的核心安全风险，而现有的允许/拒绝式监视器必须在证据积累之前就做出决定。通过将决策推迟到后续证据可用时，Kairos 在攻击成功率与效用之间提供了更好的权衡，可能影响代理平台在系统边界上实施安全防护的方式。 Kairos 将工具调用、shell 命令和代理编写的脚本都视为跨越隔离边界的相同文件与网络操作，因此无论代理行为如何，隔离约束都能成立。声明式策略确定性地决定大多数效果并推迟其余效果，被推迟的效果在代理继续推测性执行时被暂存，而具有受限权限的决策预言机（如语言模型或人类）会释放或拒绝每个被推迟的效果。

rss · arXiv Agent Infra · 10月13日 14:24

**背景**: 引用监视器是一种经典的安全设计，由单一机制调解主体与客体之间的所有访问请求并执行访问控制策略；它被认为表达了任何做出安全声明的系统所必需且充分的性质。LLM 代理正越来越多地获得对文件、网络和工具的广泛访问权限，而由于模型无法可靠地区分指令与数据，它们摄入的任何内容都可能携带注入的指令。间接提示注入正是利用这一点，将恶意指令隐藏在代理读取的内容中，而仅对单个动作进行允许或拒绝的防御往往难以奏效，因为合法工作与攻击的第一步常常看起来十分相似。

## [加密技能注入：将恶意指令隐藏在编码技能文件中攻击 LLM 智能体](https://arxiv.org/abs/2610.18262v1) ⭐️ 8.0/10

一篇新论文提出了加密技能注入（CSI）技术，将恶意指令嵌入编码后的技能文件中，让 LLM 智能体自行解码并执行。该研究在八个模型和 139 对注入-任务组合上进行了评估，凯撒密码和分层密码变体的攻击成功率分别最高达到 47.5%和 40.3%，而现有技能扫描器几乎无法标记出这些被注入的技能。 这揭示了 LLM 智能体面临的一种新型供应链攻击向量：看似无害的第三方技能可以携带隐藏的恶意指令，绕过当前的安全扫描器。随着智能体生态越来越依赖社区贡献的技能，这威胁到任何将解码后的不可信内容提升为可执行指令的平台的安全性。 该研究将指令恢复与攻击成功分开评估，发现成功解码并不保证攻击成功，且分层加密的效果因模型而异。在缩短技能的主要设置下，两种变体的攻击成功率分别达到 47.5%和 40.3%，而测试的技能扫描器很少能标记出被注入的技能。

rss · arXiv Agent Infra · 10月13日 12:25

**背景**: 提示注入是一种攻击方式，攻击者将恶意文本插入 LLM 的输入中，使模型将其当作合法指令执行，其根源在于 LLM 应用无法清晰区分开发者指令与用户输入。LLM 智能体通常会从社区来源加载第三方“技能”——可复用的指令或代码文件——为此出现了 Cisco AI Defense 的 skill-scanner 等安全扫描器，用于检测这些技能中的提示注入、数据外泄和恶意代码模式。CSI 在此基础上进一步将恶意指令编码（如凯撒密码或分层密码），让智能体自行解码并执行，从而绕过基于模式的检测。

## [RT-J：8500 万参数关系 Transformer 将上下文示例减少 10 倍](https://arxiv.org/abs/2610.17867v1) ⭐️ 8.0/10

研究人员提出了 RT-J，一个 8500 万参数的关系基础模型，在名为“the Join”的数据集上预训练，该数据集包含 639 个网络爬取的数据库和 6023 个由大语言模型生成的预测任务，上下文长度可达 8192 个数据库单元。在 RelBench 的上下文回归任务上，RT-J 平均只需十分之一的上下文示例即可匹敌强大的特征工程流水线。 这项工作推动了关系数据上上下文高效预测的前沿，有望减少在新数据库上部署预测模型所需的数据和工程投入。它表明关系基础模型的发展势头日益增强，可能服务于依赖结构化表格的科学和工业领域。 RT-J 采用一种新颖的轻量级随机游走检索器来选择上下文示例，并利用上下文调优和集成来扩展测试时计算。它以长达 8192 个数据库单元的长上下文进行预训练，并与包括 LLM-agent 或 RDBLearn 特征器配合 TabICLv2 或 LightGBM 预测器的基线方法进行了对比评估。

rss · arXiv Agent Infra · 10月13日 07:27

**背景**: 关系基础模型旨在许多不同的关系数据库上预训练一个高容量模型，使其无需针对每个数据库构建流水线即可对未见过的表格进行预测。上下文学习使这类模型能够通过在提示中提供少量示例来适应新任务，但现有方法通常需要数万个示例。RelBench 是一个关系深度学习基准，对关系数据库上的分类和回归方法进行排名。
